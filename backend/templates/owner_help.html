👨‍🏫 Professor Management

Create Invitation

  1. Navigate: P → Create Invitation
  2. Fill form:
    • Organization - Target org
    • Email - Professor's email
    • Expires In - 1-168 hours (default 48)
    • Max Uses - Usually 1
    • Notes - Internal tracking
    • Change Ticket - Optional CM reference
  3. Click Create Invitation
  4. ⚠️ COPY SECRET IMMEDIATELY - shown once only!
Invitation Secret Format: PROF-ABCD-EFGH
Professor uses this during first signup. Secret is never shown again.

Pre-create Professor

  1. P → Pre-create Professor
  2. Enter: Email, Name, Organization, Temporary Password
  3. Account created in pending status

Cleanup Plans ⚠️ DESTRUCTIVE

⚠️ PERMANENTLY DELETES DATA
Only for test/demo data. Production data cleanup requires emergency DBA approval.

Create Plan

  1. B → Create Cleanup Plan
  2. Define scope (JSON selector):
{
  "organizations": ["org-uuid-1"],
  "sessionStatus": ["completed", "archived"],
  "olderThanDays": 90,
  "includeResults": true,
  "includeDecisions": true,
  "includeTeams": false
}
  1. Click Preview → Review row counts per table
  2. Click Create Plan → Generates plan with hash

Execute Plan

  1. Select plan → Execute
  2. Type exact phrase: DELETE TEST DATA PERMANENTLY
  3. Requires: Recent auth + MFA
  4. Monitor in Cleanup Plans table

Plan Status

StatusMeaning
pendingCreated, not executed
executingCurrently running
completedFinished successfully
failedError (check audit log)

🔒 Security Features

MFA Required

TOTP-based (Google Authenticator, Authy)

Recent Auth

15-minute window for sensitive ops

Idempotency Keys

Prevent duplicate mutations on retry

Rate Limiting

60 req/min API, 10/min auth, 1/hr cleanup

Idempotency Key Usage

curl -X POST https://api.practenture.com/api/owner/users/123/suspend \
  -H "Authorization: Bearer " \
  -H "Idempotency-Key: suspend-user-123-20260726-001"

Key must be unique per operation. Stored 24 hours.

Secrets Never Logged

  • Passwords & token hashes
  • Access/refresh tokens
  • MFA secrets
  • Invitation secrets
  • Database credentials
